## 1. Where C Compilers Look for Headers

### General C Compiler Header Search Order

C compilers (like GCC, Clang, MSVC) search for header files in a specific order:

1. **Current Directory** - For quoted includes (`#include "header.h"`)
2. **`-I` (Include Path) Directories** - Specified via command line (in order specified)
3. **System Include Directories** - Standard system paths like:
   - `/usr/include`
   - `/usr/local/include`
   - Compiler-specific directories (e.g., `/usr/lib/gcc/x86_64-linux-gnu/12/include`)
4. **Framework Directories** (macOS) - `-F` paths and system frameworks

### Two Types of Includes

| Syntax | Search Order | Use Case |
|--------|--------------|----------|
| `#include "file.h"` | Current dir → `-I` paths → system paths | Project headers |
| `#include <file.h>` | System paths only (skips current dir) | System/library headers |

### GCC Header Search Path Example

```bash
# View default search paths
gcc -xc -E -v /dev/null

# Add custom include path
gcc -I../include -I/usr/local/include myfile.c
```

## 3. NetHack Build System - How Headers Are Found

### From `sys/unix/Makefile.src`

```makefile
# Root of source tree
NHSROOT=..

# Include path flag - tells compiler where to find headers
CFLAGS ?= -I../include

# For specific configurations
CFLAGS = -O -I../include

# Compilation rule for .c to .o
$(TARGETPFX)%.o : %.c
	$(TARGET_CC) $(TARGET_CFLAGS) -c -o $@ $<
```

The `-I../include` flag tells the compiler to look in the `include/` directory for headers.

### Header Dependencies in Makefile

```makefile
# Timestamp files to track header changes
CONFIG_H = ../src/config.h-t
HACK_H   = ../src/hack.h-t

# Object files depend on headers
$(TARGETPFX)nhlua.o: nhlua.c $(HACK_H) ../include/dlb.h
$(TARGETPFX)monst.o: monst.c $(CONFIG_H) ../include/align.h ...
$(TARGETPFX)objects.o: objects.c $(CONFIG_H) ../include/defsym.h ...
```

### Example: nhlua.h Generation

The Lua integration header is generated to point to the correct Lua installation:

```c
/* sys/msdos/nhlua.h - template */
```

## 4. The C Compilation Process (4 Stages)

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   Source     │    │ Preprocessor │    │   Compiler   │    │   Linker     │
│  (.c/.h)     │───▶│    (cpp)     │───▶│   (cc1)      │───▶│    (ld)      │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
                           │                   │                  │
                    [Headers inserted      [Assembly        [Libraries
                     & macros expanded]      generated]        linked]
```

### Stage 1: Preprocessing (`cpp`)

**Command:** `gcc -E file.c`

**What happens:**
- Processes `#include` directives (inserts header content verbatim)
- Expands `#define` macros
- Handles `#ifdef`, `#ifndef`, `#if` conditional compilation
- Removes comments
- **Headers are fully resolved and inserted here**

**Output:** Expanded `.i` file (pure C code, no preprocessor directives)

**Example:**
```c
// Input: nhlua.c
#include "hack.h"
#include <setjmp.h>
#define BUFSZ 256

// After preprocessing: 10,000+ lines from all included headers
// + setjmp.h content
// + BUFSZ replaced with 256 everywhere
```

### Stage 2: Compilation (`cc1`)

**Command:** `gcc -S file.c`

**What happens:**
- Parses the expanded C code
- Performs syntax and semantic analysis
- Generates assembly code for the target architecture
- Optimizations applied here

**Output:** `.s` assembly file

**Note:** No headers exist at this stage - they've been expanded into the source.

### Stage 3: Assembly (`as`)

**Command:** `gcc -c file.c` (or `as file.s -o file.o`)

**What happens:**
- Converts assembly instructions to machine code (binary)
- Creates object files with:
  - Machine code
  - Symbol tables (function/variable names)
  - Relocation information
- **External references are noted but NOT resolved**

**Output:** `.o` (or `.obj` on Windows) object file

**Symbol table example:**
```
00000000 T main          # T = text (code), defined here
         U printf        # U = undefined, needs to be linked
         U malloc
```

### Stage 4: Linking (`ld`)

**Command:** `gcc -o program file1.o file2.o -llib`

**What happens:**
- Combines all `.o` object files into one executable
- **Resolves external function calls** (finds `printf` in libc, etc.)
- **Links libraries** (static `.a` or dynamic `.so`/`.dll`)
- Arranges code and data in memory layout
- Creates final executable format (ELF, PE, Mach-O)

**Output:** Executable file

## 5. Header Usage in C

### What Headers Contain

Header files typically contain:

| Content | Example |
|---------|---------|
| Function declarations/prototypes | `extern void l_nhcore_init(void);` |
| Type definitions | `struct monst { ... };` |
| Macro definitions | `#define TELL 1` |
| External variable declarations | `extern struct you u;` |
| Constant definitions | `#define BUFSZ 256` |
| Inline function definitions | `static inline int max(int a, int b) { ... }` |

### Include Guards

Every header must use include guards to prevent multiple inclusions:

```c
#ifndef HACK_H
#define HACK_H

// ... header content ...

#endif /* HACK_H */
```

Without guards, including the same header twice would cause "redefinition" errors.

### NetHack Header Example: `include/hack.h`

```c
/* NetHack 3.7	hack.h	... */
#ifndef HACK_H
#define HACK_H

#ifndef CONFIG_H
#include "config.h"
#endif
#include "lint.h"

#include "align.h"
#include "weight.h"
#include "dungeon.h"
#include "stairs.h"
#include "objclass.h"
#include "wintype.h"
#include "flag.h"
// ... 20+ more includes ...

/* Type definitions */
struct breadcrumbs {
    const char *funcnm;
    int linenum;
    boolean in_effect;
};

/* Enum definitions */
enum game_end_types {
    DIED         =  0,
    CHOKING      =  1,
    POISONING    =  2,
    // ...
    ASCENDED     = 15
};

/* Macro definitions */
#define TELL 1
#define NOTELL 0
#define ON 1
#define OFF 0
#define BOLT_LIM 8

/* Function prototypes */
extern void l_nhcore_init(void);
extern void l_nhcore_done(void);
extern void l_nhcore_call(int);

/* External variables */
extern struct you u;
extern struct flag flags;

#endif /* HACK_H */
```

### Source File Using Headers: `src/nhlua.c`

```c
#include "hack.h"    // Project header - uses quotes
#include "dlb.h"     // Project header

#ifndef LUA_VERSION_RELEASE_NUM
#ifdef NHL_SANDBOX
#undef NHL_SANDBOX
#endif
#endif

#ifdef NHL_SANDBOX
#include <setjmp.h>    // System header - uses <>
#endif

// ... function implementations ...
```

## 6. When Libraries Are Linked

### Static Libraries (`.a` / `.lib`)

| Aspect | Description |
|--------|-------------|
| Linking Time | Compile time (Stage 4) |
| How it works | Library code is copied into the executable |
| Executable size | Larger |
| Runtime dependency | None (self-contained) |
| Example | `liblua.a`, `libncurses.a` |

### Dynamic/Shared Libraries (`.so` / `.dll` / `.dylib`)

| Aspect | Description |
|--------|-------------|
| Linking Time | Load time (when program starts) |
| How it works | Library code is shared between programs |
| Executable size | Smaller |
| Runtime dependency | Requires library file at runtime |
| Example | `libc.so.6`, `libX11.so` |

### NetHack's Library Linking

From `sys/unix/Makefile.src`:

```makefile
# Lua library
LUA_VERSION ?=5.4.8
LUABASE = liblua-$(LUA_VERSION).a
LUALIB = ../lib/lua/$(LUABASE)
LUALIBS = $(LUALIB) -lm $(DLLIB)

# Link command (Stage 4)
Sysunix: $(HOSTOBJ) $(HOBJ) $(TARGET_HACKLIB) $(DATE_O) $(BUILDMORE) Makefile
	@echo "Linking $(GAME)."
	$(AT)$(TARGET_LINK) $(TARGET_LFLAGS) -o $(GAMEBIN) \
		$(HOBJ) $(DATE_O) $(TARGET_HACKLIB) $(WINLIB) \
		$(TARGET_LIBS) $(LUALIBS) $(AUTOLIBS)
```

### Libraries NetHack Uses

| Library | Flag | Purpose | When Linked |
|---------|------|---------|-------------|
| `liblua-5.4.8.a` | `$(LUALIB)` | Lua scripting engine | Link stage |
| `-lm` | Hardcoded | Math library (sqrt, sin, etc.) | Link stage |
| `-lncurses` | `$(WINCURSESLIB)` | Terminal UI library | Link stage |
| `-lX11` | `$(WINX11LIB)` | X11 graphics | Link stage |
| `-lQt5*` | `$(WINQT5LIB)` | Qt GUI framework | Link stage |
| `-lz` | `$(LIBS)` | zlib compression | Link stage |
| `hacklib.a` | `$(TARGET_HACKLIB)` | NetHack utility library | Link stage |

## 7. Summary Table

| Stage | Tool | Input | Output | Headers | Libraries |
|-------|------|-------|--------|---------|-----------|
| **Preprocess** | `cpp` | `.c` + `.h` | `.i` | **Inserted here** | Not used |
| **Compile** | `cc1` | `.i` | `.s` | Already expanded | Not used |
| **Assemble** | `as` | `.s` | `.o` | Not present | Not used |
| **Link** | `ld` | `.o` + libs | Binary | Not present | **Linked here** |

### Key Points

1. **Headers are used during preprocessing** - they provide declarations that the compiler needs to verify type correctness
2. **Headers don't contain code** - they only declare what's available
3. **Libraries are linked at the final stage** - they provide the actual implementation of functions
4. **Include paths (`-I`) affect preprocessing** - they tell the preprocessor where to find headers
5. **Library paths (`-L`) affect linking** - they tell the linker where to find libraries

## 8. NetHack Build Flow

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           NETHACK BUILD PROCESS                              │
└─────────────────────────────────────────────────────────────────────────────┘

PHASE 1: Setup
├── Generate include/nhlua.h (from sys/msdos/nhlua.h template)
├── Generate include/date.h (using makedefs -v)
└── Prepare configuration headers

PHASE 2: Compile Object Files (Stage 1-3 for each file)
├── src/allmain.c → src/allmain.o
├── src/alloc.c → src/alloc.o
├── src/apply.c → src/apply.o
├── ... (100+ source files)
├── sys/share/ioctl.c → sys/share/ioctl.o
├── sys/unix/unixmain.c → sys/unix/unixmain.o
├── win/tty/wintty.c → win/tty/wintty.o
└── win/curses/cursmain.c → win/curses/cursmain.o

PHASE 3: Create Static Libraries
├── Create hacklib.a (from hacklib.o)
└── Use liblua-5.4.8.a (pre-built or compiled)

PHASE 4: Link Everything (Stage 4)
├── Link all .o files
├── Link hacklib.a
├── Link liblua-5.4.8.a
├── Link -lm (math)
├── Link -lncurses (or other window library)
└── Output: nethack executable
```

### Full Makefile Dependencies

```makefile
all: $(GAME)

$(GAME): pregame $(MAKEDEFS) $(LUALIB) $(SYSTEM)

Sysunix: $(HOSTOBJ) $(HOBJ) $(TARGET_HACKLIB) $(DATE_O) Makefile
	$(TARGET_LINK) $(TARGET_LFLAGS) -o $(GAMEBIN) \
		$(HOBJ) $(DATE_O) $(TARGET_HACKLIB) $(WINLIB) \
		$(TARGET_LIBS) $(LUALIBS)

# Object file compilation (Stages 1-3)
$(TARGETPFX)%.o : %.c
	$(TARGET_CC) $(TARGET_CFLAGS) -c -o $@ $<

# Dependencies ensure headers trigger recompilation
$(TARGETPFX)nhlua.o: nhlua.c $(HACK_H) ../include/dlb.h
$(TARGETPFX)hack.o: hack.c $(HACK_H)
$(TARGETPFX)monst.o: monst.c $(CONFIG_H) ../include/monsters.h
```

## Quick Reference

### Compiler Flags for Headers

| Flag | Purpose | Example |
|------|---------|---------|
| `-I<dir>` | Add include directory | `-I../include` |
| `-D<name>` | Define macro | `-DDEBUG` |
| `-D<name=value>` | Define macro with value | `-DBUFSZ=512` |
| `-E` | Stop after preprocessing | `gcc -E file.c` |
| `-M` | Show header dependencies | `gcc -M file.c` |

### Compiler Flags for Libraries

| Flag | Purpose | Example |
|------|---------|---------|
| `-L<dir>` | Add library directory | `-L/usr/local/lib` |
| `-l<name>` | Link library | `-llua -lm -lncurses` |
| `-static` | Static linking | `gcc -static file.c` |
| `-shared` | Create shared library | `gcc -shared -o lib.so *.o` |

### NetHack-Specific

| Path | Purpose |
|------|---------|
| `include/` | All NetHack headers |
| `include/hack.h` | Master header (includes most others) |
| `sys/unix/Makefile.src` | Unix build rules |
| `lib/lua*/` | Lua library headers and source |
| `src/*.c` | Main source files |
| `sys/share/*.c` | Shared system code |
| `win/*/*.c` | Window port implementations |
